# Как оформляем коммиты

## Сообщение коммита

Формат — `тип(область): краткое описание изменения`. Описание пишем по-русски, со строчной буквы, с точкой в конце.

```text
feat(front): добавлена страница авторизации.
```

## Типы коммитов

| Тип | Когда использовать |
| --- | --- |
| `feat` | Добавили новую функциональность. |
| `fix` | Исправили ошибку. |
| `refactor` | Изменили структуру кода без изменения его поведения. |
| `docs` | Добавили или обновили документацию. |
| `test` | Добавили или обновили тесты. |
| `style` | Исправили форматирование кода. |
| `perf` | Улучшили производительность. |
| `build` | Изменили сборку или зависимости проекта. |
| `ci` | Изменили настройки или сценарии CI. |
| `chore` | Выполнили служебную задачу, например обновили настройки редактора. |

Область показывает, где внесено изменение. Для фронтенда используем `front`, для бэкенда — `back`.

## Размер коммита

Один коммит — одно логически законченное изменение. Если задача состоит из нескольких самостоятельных шагов, делаем отдельный коммит на каждый шаг. Включаем в коммит файлы, нужные для этого изменения, и сохраняем проект в рабочем состоянии после каждого шага.

Например, работу над страницей авторизации можно разбить так.

```text
feat(front): сверстана страница авторизации.
feat(front): подключена форма авторизации к API.
feat(front): добавлено отображение ошибок авторизации.
```
